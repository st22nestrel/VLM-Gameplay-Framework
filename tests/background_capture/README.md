# Background capture tests

All tests for the background-window feature live here. Use the `transformers5`
environment, from the repository root.

## Three-move Chess Titans input baseline

```powershell
python tests/background_capture/chess_moves.py --new-game
```

This opens/reuses Chess Titans, starts a new game, and plays **three White turns**
(`a2-a3`, `b2-b3`, `c2-c3`; six separate clicks) against the computer. `--new-game`
abandons an existing game using F2 and its confirmation; Chess Titans may count
that as a loss. Omit it when the board is already in its initial position.
The game stays open after the test. Keep the desktop unlocked and avoid using
the mouse or changing focus during replay.

The recorded layout is **800x496 client pixels**, White at the bottom, the default
stone board/pieces and the camera shown in
[`fixtures/chess_moves/initial.png`](fixtures/chess_moves/initial.png). This is an
explicit calibrated fixture: a different size, theme, camera or starting board
fails validation before the move clicks. Every run waits up to 15 seconds for
the initial board, including the first-launch loading screen and new-game camera
animation. Use `--startup-timeout 60` for a slower launch. The replay does not
resize windows or change settings.

| Turn | Source click | Destination click |
| --- | --- | --- |
| a2-a3 | (212, 346) | (218, 308) |
| b2-b3 | (266, 346) | (270, 308) |
| c2-c3 | (320, 346) | (322, 308) |

These clicks were found by actually playing through `python -m src.control`.
Each source click settles for 400ms. Each destination click waits **at least
3 seconds**, then polls every 500ms until the six pawn/source patches match the
recorded state, the hourglass is absent, and Black's board region has changed
and stayed stable across two successive comparisons. Opponent moves may vary;
the test does not require the recorded Black moves. Each turn times out after
60 seconds. Use `--opponent-wait 5 --timeout 120` for a slower opponent.

The replay uses the `click_at` canonical action directly, alongside `new_game`.
Game and confirmation-dialog sessions explicitly load the replay's two-action
fixture, without an action-count preflight check. The selected action name,
config path, loaded action names, Python executable and startup observations are
included in `results.json` to diagnose configuration or launch failures.

Raw PrintWindow screenshots, input/execution details, per-check image errors and
pass/fail results go to `outputs/background_capture/chess_moves_<timestamp>/`.
Use `--out <directory>` for a fixed location. Exit codes are 0 for success, 1 for
failure and 130 for interruption. A no-op input sender cannot pass the visual
checks. Stored fixtures are cropped from the manually verified run, and are
not regenerated by a replay.

Run the live test through pytest (explicitly opt-in; also resets the board):

```powershell
python -m pytest tests/background_capture/test_chess_moves.py --live-chess-moves -q
```

This establishes the **foreground input baseline** for future covered-window
input. It uses `GameSession.step` and background screenshots; input still focuses
the game. `replay(game, ...)` keeps the click fixture and visual assertions
independent of session construction so the same sequence can later exercise a
background input implementation. A future covered-window test must also assert
that its covering window retains focus and the real cursor stays unchanged.

Select the input sender and focus policy independently:

```powershell
python tests/background_capture/chess_moves.py --new-game --input-method postmessage
python tests/background_capture/chess_moves.py --input-method postmessage --allow-unfocused
python tests/background_capture/chess_moves.py --input-method sendinput --allow-unfocused
```

Defaults remain `sendinput` with focus required. `--allow-unfocused` skips
automatic activation and focus guards for either sender. Settings are included
in `results.json` and step records. The game/dialog sessions use the same settings.
Prepare/reset the board while focused before trying a covered replay, then omit
`--new-game` for that replay. F2 and `click_at` still use direct input where
applicable; disabling focus checks can send input to a covering application.
The sendinput and legacy postmessage methods implement the six `click_at` actions with
SetCursorPos + SendInput, so this switch alone does not make chess clicks work
through a covering window.

### Window-directed Chess Titans input

```powershell
python -m pip install -r requirements-windowmessage.txt
python tests/background_capture/chess_moves.py --input-method windowmessage --allow-unfocused
```

This works with Chess Titans covered and inactive. Its mouse translator reads
`GetCursorPos` instead of the coordinates carried in mouse messages. The backend
therefore loads a temporary process-local Frida cursor hook for `ChessWindowClass`.
Only the recipient thread's cursor reads during synchronous mouse dispatch see
the virtual position; desktop cursor/focus stay unchanged. Keyboard messages
stay queued so F2 still reaches the game's accelerator loop. Sessions detach
the hook on stop. Other windows continue to use ordinary posted messages.

For repeatable verification, the following runs the same replay behind an owned
foreground window, checking focus and cursor at every observation:

```powershell
python tests/background_capture/chess_moves_covered.py --new-game
```

The actual covered-game replay passed all three moves and opponent replies.
This confirms Chess Titans support; it does not establish DirectInput/Raw Input
support for other games. See [implementation notes](../../docs/background-input.md).

## Interactive Chess Titans test

```powershell
conda activate transformers5
python tests/background_capture/chess_titans.py
```

This opens Chess Titans automatically (or uses its already-open window), then
waits for Enter. Prepare the board, cover the game with another window without
minimizing it, and return to the terminal to press Enter. The terminal itself
can cover the game. The test takes ten raw screenshots one second apart while
leaving focus alone, and prints their paths. Chess Titans stays open afterward.

Images and `results.json` go to `outputs/background_capture/chess_<timestamp>/`.
Inspect the PNGs: they should show the board, including its covered portions,
with no pixels from the covering window. Foreground/minimized attempts are
skipped and capture failures are recorded. A successful capture is not an
automatic assertion that Chess Titans rendered correctly; inspect the images.

For a different installation or a longer run:

```powershell
python tests/background_capture/chess_titans.py --exe "D:\Games\Chess\chess.exe" --count 30 --interval 1
```

Run it twice to check partial and full coverage. To check freshness, first make
a move, cover the game while the computer is thinking, then start capture and
look for the computer's move in subsequent screenshots.

## Automated regression tests

Offline regression tests (no desktop interaction):

```powershell
conda run -n transformers5 python -m pytest tests/background_capture -q
```

Live regression tests create and close their own target and covering windows.
They temporarily activate the cover window. They require an unlocked Windows
desktop; avoid switching windows during the run.

```powershell
conda run -n transformers5 python -m pip install -r tests/background_capture/requirements.txt
conda run -n transformers5 python -m pytest tests/background_capture --live-background-capture -q
```

The live matrix covers GDI (Tk canvas) and GPU-rendered OpenGL (SDL/pygame):

| Check | Assertion |
| --- | --- |
| Partial coverage | Every captured client pixel matches the target |
| Full coverage | Every captured client pixel matches the target |
| Freshness | Changing content while covered appears in the next capture |
| Positive control | MSS sees the magenta cover, proving actual occlusion |
| Focus and position | Cover stays foreground; target does not move |
| Input focus policy | Both senders reject an unfocused wait by default and allow it with `--allow-unfocused`, keeping cover focus and cursor position |
| Minimized target | No frame; target remains minimized |

OpenGL cases skip if the optional test dependency `pygame` is absent. The normal
test run skips all live cases unless `--live-background-capture` is supplied.
Test windows run in a separate process so their UI event loop stays responsive
during PrintWindow calls. Captures go to pytest's temporary directory.

On this development machine, existing PrintWindow passed the GDI and OpenGL
coverage/freshness checks, while MSS captured the cover as expected. This is
evidence for these renderers, not a guarantee that every game implements
PrintWindow correctly. Test the actual target game before unattended use.
